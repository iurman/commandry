# ADR 0016: Project the operational Observatory

**Status:** Accepted

**Date:** 2026-10-16

**Authority:** Direct owner approval of the operational-landscape packet and its recommended defaults on 2026-10-16.

## Context

ADR 0015 established one complete Gravity landscape. Treating every inventory root as a host basin obscures actual operations, and allocating terrain detail to duplicate previous/next identities reduces curvature. A canonical repository is not necessarily a deployed application or an observed service.

## Decision

Preserve ADR 0015's complete authorized population, canonical identities, continuation, same-scope delayed refresh, accessible fallback and no visible resource pages. Supersede only its implication that each inventory resource must always be a distinct GPU well. Every authorized resource belongs to an explicit aggregate or expanded representation. Unique membership conservation is independent of active representation/GPU coverage; both require tests. References disclose aliases and never increase canonical totals.

Use a deterministic domain/application projection with distinct host, deployment, provider, repository and collection meanings. Authorize entities, relations and facets before computing any membership, counts, summaries or inherited evidence. Preserve physical containment separately from presentation grouping. Explicit reviewed mappings establish deployment and provider relationships; names and project co-membership cannot.

Default to the operational landscape, structural child/service sizing, compact repository collections, composed still camera and click-to-focus/inspect. Provide deliberate orbit/tour, a smaller optional lens, complete outline/search and configurable views. Stable positions and label anchors preserve reading context. Retain Three.js and improve active-basin detail without resource caps.

Availability, telemetry freshness, monitoring coverage, capacity, lifecycle, security, provider relevance and work are independent evidence-bearing facets. Only fresh qualifying observations establish passing checks. Cloudflare status notices initially use its official structured API. Severity, relevance, confidence, independently confirmed local impact and causal attribution remain separate. Static dependencies do not imply traffic.

UI, API and independently granted MCP use the same application services and canonical records. Existing grants and legacy tools do not expand. Canonical mapping/view writes require explicit scoped operations, expected versions, provenance and immutable audit. Device-local camera/lens/theme controls may remain owner UI-only with that boundary documented. No new dispatcher or monitoring platform is authorized by this decision.

## Consequences

Verify the mixed 91-resource shape, rich operational/adversarial fixtures, authorization before aggregation, active GPU coverage, smooth silhouettes, stable labels and shared overlay usability. Preserve backward-compatible flat infrastructure responses. Operational activation, physical device claims and production readiness require their own actual evidence. Follow the existing constrained deployment, backup/restore, provenance and owner gates.

## Alternatives considered

Equal craters for all inventory rows obscure meaning. Fixed caps or visible resource pages violate complete-scene access. A replacement graph dashboard, rendering engine, monitoring platform or agent dispatcher is unnecessary. Decorative requests and inferred mappings would misrepresent evidence.
