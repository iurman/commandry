# Preserve automatic guided-tour progression

Status: Proposed correction to a confirmed actual built E05 defect on source20a6967. A natural guided tour starts correctly, then selects its first featured host after about 2.5 seconds without direct input. The renderer sends that automatic feature through the same select hook used by pointer picking. OperationalObservatory calls activate(), which sets camera manual; its focus callback also interrupts renderer presentation. The tour stays manual thereafter. Slow orbit continues and stops on real drag, narrowing the failure to automated tour selection.

## Change

Distinguish automated featured-subject updates from direct activation at the shared renderer/UI boundary. An automatic tour feature may update the existing subject highlight/inspector with exact identity, but must preserve tour mode, elapsed progression, approach/dwell/retreat and camera ownership. It must not feed back into focusSubject's interruption path, emit manual expansion/query transitions, push artificial reading history or remount controls merely to feature a host. Real pointer/keyboard/search/outline/inspector interaction must still interrupt deliberate tour/orbit and require explicit resumption. Preserve reduced motion, pause, scope/permission resets and direct Back/focus behavior. Do not remove direct activation interruption or hide the selected subject to make the tour appear continuous.

Preserve compatible existing renderer consumers. An optional hook origin or separate optional automatic-feature callback is acceptable if its semantics are explicit and existing consumers remain type-safe. New product meaning remains in the actual OperationalObservatory interaction; no new control, setting, domain authority or runtime/Work inference.
