# Current-head pull request checks

Status: Proposed correction to the B06 acceptance gap. The existing repository adapter supplies real PR identities and scanner evidence, but no current-head CI result. The owner authorized the complete operational upgrade, including failed PR checks as a development concern independent of service availability.

## Supported read contract

Use GitHub's official GET endpoints for [check runs at a Git reference](https://docs.github.com/en/rest/checks/runs#list-check-runs-for-a-git-reference) and [commit statuses](https://docs.github.com/en/rest/commits/statuses#list-commit-statuses-for-a-reference). Pin each request to the exact PR head commit supplied by the open-pulls response, using the configured base repository. Check-run lists are objects with total_count and check_runs; status lists are arrays. Follow validated continuation with unchanged filters. Check runs have status/conclusion and original started/completed times; status contexts have state and original created/updated times. Read permissions can fail independently. Empty visible results do not establish required-check success or branch-protection satisfaction. No writes, reruns or merge action is included.

## Required behavior

Extend the existing derived PR record additively with optional headSha and independent check-run/status evidence. Old persisted PR evidence without these fields remains readable and visibly unknown. Newly collected missing/invalid head identity is unknown, never a successful empty check read. Current responses must retain exact head binding and safe official links; do not follow source html_url, details_url, status target_url or PR head repository URLs. A current failed CI check must be readable alongside pending/unknown CI, source denial and scanner findings without affecting service availability, manufacturing an AgentRun or promoting a PR into an active coding run. Keep original observation times; source read time is not completion time.

For each unique valid head, issue only computed read endpoints inside the configured repository/origin. Reuse the existing transport deadline/size/encoding/continuation/secret guards, safe failure codes and independent-component handling. Bound concurrent head reads; do not introduce a total PR/head/result cap or unbounded fan-out. Shared head SHAs may reuse a single read. Preserve partial facet failures without erasing successful independent security evidence. Preserve complete original bodies privately with a wrapper-compatible depth guard; never retain configured token/literal secret or raw body excerpts in public DTOs. Do not label a successful list or a skipped/neutral check as proof that all required checks passed.

Render current-head identity, each supported check's actual state/time, complete-source versus unavailable status and an explicit required-check-coverage caveat in the existing repository PR details. Literal names/context text remain inert. Use existing scoped evidence UI/API/MCP paths and authority. Declare no new action or grant. This is an evidence extension, with no new operational control.
